# Gateway 产品数据边界

本文件是 `backend/app/gateway/AGENTS.md` 中 Flow Desk 数据边界的详细说明。修改 Gateway 的 owner 数据读取、删除、审计或文件目录能力前，请先阅读相应段落；产品扩展只能使用公开 Extension API。

Extension API `0.2.17` 增加异步 `require_data_scope(request, target, action, resource_id)`，
`0.2.18` 增加后台 owner-data authorizer 合约。
Gateway 将其接到 `require_iam_data_scope_for_request()`，因此扩展可在读写自有产品表前
同时检查 Gateway route grant 与中央 IAM 的 owner/self scope，而无需导入 `app.*`。
中央拒绝按 403 处理；Provider 不可用、scope 不可映射或宿主未安装能力按 503 失败关闭。
本地 RBAC 模式下，宿主 checker 沿用 Gateway 的 no-op 语义。调用仅属于当前 HTTP 请求，
扩展不得把请求对象或 IAM 凭据保存到任务、日志或 checkpoint。

数据导出/删除 worker 以持久化 owner ID 调用 Gateway 的 owner-scoped reader/deleter，
并通过 `ExtensionRuntimeDeps.owner_data_authorizer` 在领取任务、分页/删除检查点重新解析当前权限。
Gateway 每次重新加载活跃本地账号；Central IAM 配置下再从服务端 token vault 刷新当前会话，
重新检查每个范围的 route grant 和 owner/self data scope。IAM 凭据、请求对象和授权结果不写入任务行。
403 撤权会以稳定的 `authorization_revoked` 错误终止任务；503 授权服务故障以
`authorization_unavailable` 进入有界重试。产品服务启用后台任务却未注入 authorizer 时启动失败。
直接构造 worker 的离线单测可省略该宿主能力，但部署服务不得如此配置。

任务历史列表按每条任务的 kind/scope 重验当前 route grant 与 data scope；已撤权范围的条目不返回，
授权服务不可用时整个列表返回 503。列表按原始 owner 分页推进，隐藏条目仍占用数据库 offset，
客户端应允许继续翻页，不能把过滤后的短页误判为已到末尾。

Flow Desk 的后台数据导出通过可选的 `ExtensionRuntimeDeps.owner_data_reader`
读取宿主数据。调用必须传入任务持久化的 owner ID；线程和项目仓储先按 owner
过滤，Gateway reader 再检查归属并投影固定字段。项目页使用稳定的有界分页，
只返回名称、说明、展示配置、状态和时间戳；不能暴露项目文档字节、checkpoint
或删除能力。计划任务导出也通过此 reader 按 owner 分页读取任务定义，字段限定为
标题、提示词、助手、调度频率、时区、状态及时间戳；不得返回运行历史、运行 ID、
运行时错误或租约信息。reader 未装配时必须返回不可用状态并让导出失败关闭。调整此契约时，
同步维护公开 extension-api、产品扩展 worker、范围 DTO、双语提示和补丁台账。

线程历史导出还可通过 `OwnerDataReader.list_thread_runs(user_id, thread_id, ...)`
读取运行摘要。Gateway 必须先确认线程 owner，再向 RunStore 显式传入相同 owner；只投影
运行 ID、Agent ID、状态、时间和 token 计数，排除原始请求参数、错误正文、任意 metadata、
stop reason、内部操作记录及 worker lease。运行分页按 `(created_at, run_id)` 倒序，游标
必须向更旧记录推进。旧宿主缺少该可选能力时，导出保持 `partial` 并写明运行摘要未覆盖。

计划任务、自建 Agent、本人会话、本人项目空间和记忆清空使用独立可选的 `ExtensionRuntimeDeps.owner_data_deleter`，不得并入只读 reader。计划任务通过 `ScheduledTaskRepository.delete_with_queue_cancellation` 在锁事务内重复校验 owner；queued occurrence 与定义一起安全处理，launching/running 保留。Agent 删除只接受 `AgentStore.list_owned` 返回的个人定义，并调用 `AgentStore.delete(name, user_id=...)`；复用普通 Agent DELETE 的记忆 debounce 前后取消，删除定义及其同目录 SOUL/记忆。部署级 legacy Agent 与没有自建定义的独立记忆目录必须保留。项目空间删除显式传 owner 调用 `ProjectRepository.delete(project_id, user_id=...)`；仓储事务删除项目定义、解除会话关联并把活动资料移入回收站，不删除会话正文或永久清空回收站。所有删除都不直接操作宿主表，worker 部分失败须复查剩余清单并报告 `partial`。记忆清空必须由 Gateway 以明确 owner ID 调用已配置记忆管理器的 `clear_memory`；仅在后端覆写该能力时开放，且清空开始后不因晚到取消请求误报失败。升级公开 API 时保持能力可选，旧宿主必须失败关闭。

受限文件删除也走同一个独立 deleter：worker 只传递 Gateway `OwnerDataReader.list_files` 生成的不透明 `file_id`，Gateway 对线程上传先用相同 owner 重验会话，再复用安全上传删除 helper；对项目资料在 `ProjectDocumentRepository.trash(..., project_id=..., user_id=...)` 的事务边界内重复检查归属。审计只记录稳定动作与线程/文档 ID，不写文件名。生成输出与工作区文件暂不开放批量删除，必须返回 `unsupported` 并让任务保留/报告 partial；完成或确认不存在后，worker 再移除当前 owner 的文件目录缓存行。旧宿主缺少可选 `supports_file_delete` / `delete_file` 时 API 必须在排队前失败关闭。

用户自建 Agent 导出必须走 `AgentStore.list_owned(user_id, limit, offset)`，不能复用
`list_custom_agents()`：文件后端的普通列表会合并部署级 legacy Agent。只投影个人可移交
设置和 `SOUL.md`，排除 `github` 仓库/安装绑定、凭据、技能正文、记忆内容与 checkpoint。
AgentStore 是同步文件/SQL 仓储，reader 必须通过线程池调用；owner 不匹配时失败关闭。
新增字段前先确认属于可移交的用户数据，并同步维护公开 extension-api 与产品 worker。

后台记忆导出必须经 `OwnerDataReader.read_memory(user_id=owner)` 读取；任务没有 HTTP
ContextVar，因此 `MemoryManager.get_memory()` 必须收到持久化任务中的明确 owner ID，并在线程池中执行。
Gateway reader 和产品 worker 都投影记忆白名单字段，排除后端私有元数据、storage revision、内部 scope
标识、凭据与 checkpoint。各记忆后端的 `get_memory` 语义可能不同（DeerMem 默认读取共享摘要和
`__default__` bucket），所以界面必须说明范围随配置后端而异，结果固定标为 `partial` 并受 10 MiB
和 5,000 条事实限制；不能据此启用完整账号导出/删除或 `data_privacy`。

Gateway 另有 `delete_custom_skills(user_id=...)` 可选能力：它只能清除经 `get_or_new_user_skill_storage(user_id)` 获取、且存储 owner 与明确 user ID 匹配的个人 custom packages、历史和状态；全局 legacy/integration 技能及其个人启用偏好必须保留，并在投影锁内重建该 owner 的技能视图、只刷新其 prompt cache。当前公开 extension-api 与产品数据任务尚未提供该删除 scope，因此不得在产品界面宣称用户可发起，也不得把它当作完整账号擦除。

用户主动的 `/api/memory/export`、`/api/memory/import`、记忆清空及事实增删改会在
Gateway 管理操作成功后向产品扩展投递稳定审计动作；事件只带记忆/事实类型和适用的 fact ID，
不得带内容、分类、请求正文或存储路径。冲突、未找到和存储错误保留原有 HTTP 响应，不能审计成成功。
Agent 对话运行期间通过 middleware/tool 自动产生的记忆更新不是这些 HTTP 管理动作，不能为了覆盖它们
在路由层推断或复制记忆正文；若要审计该路径，需另行设计运行时 observer 契约。

自定义 Agent 的创建、实际配置/SOUL 更新与删除，以及 `USER.md` 用户资料更新也投递稳定审计动作；
事件只含操作者、动作码、Agent slug（适用时）和追踪 ID，不含 Agent 描述、SOUL、模型设置或用户资料正文。
无变化的 Agent 更新、所有失败和未完成删除都不记作成功。管理 Agent API 保持按当前 Gateway owner 隔离；
变更审计时不得把上述个人内容作为资源 ID 或其他事件字段。

会话创建、分支、元数据更新、项目归属变更和删除，以及线程上传文件的创建/删除也会投递稳定审计动作。
事件只记录操作者、动作码、线程 ID 和追踪信息，不带会话标题、元数据、目标项目 ID、消息 ID、文件名或正文。
幂等命中的会话创建不重复记为新建；只有文件已完成写入且 finalize 成功后才记录上传创建。审计由可选产品
observer 尽力投递，不得让扩展故障改变 Gateway 原有的业务响应。

后台文件导出必须通过 `OwnerDataReader.read_files(user_id, max_files, max_total_bytes)`；它枚举当前 owner 的
平铺线程 `uploads/`、`outputs/`、每个会话最多遍历 200 个目录且全任务合计最多遍历 20,000 个目录的 `workspace/`，
以及项目资料架中的 active original；不读取派生预览、回收站、部署目录或任意请求路径。工作区目录树复用共享生成目录排除表，
拒绝符号链接与 Windows 联接点，并按敏感文件名模式跳过可能保存凭据的路径；文件正文不做密钥扫描，扩展必须明确提示用户
分享前复核导出。Gateway 在每次读取前重新核对线程/文档 owner；项目原件还要复核记录大小与 SHA-256。读取上限由宿主与
worker 双层执行：最多 5,000 个打包文件、7 MiB 原始字节和 10 MiB JSON 包。扩展拿到原始 bytes 和稳定来源分类，
不会拿到宿主路径；来源缺失、文件变化、目录/文件截断与项目仓储不可用必须写入部分覆盖结果。新增可导出目录前先检查
owner 根目录、symlink/junction 边界与可恢复含义，并同步维护公开 contract、reader/worker 测试、前端双语覆盖说明和升级补丁台账。

文件中心搜索使用同一 reader 的 `list_files(user_id, limit, offset, query)` 能力，返回不含正文与宿主路径的
元数据，并只构造 Gateway 自有的 owner 检查 URL。目录包括上传、产物、项目资料原件和有界的会话工作区文件；
工作区目录树复用变更扫描器的生成目录排除名单、拒绝符号链接/联接点，并限制每个工作区最多遍历 200 个目录、整次文件目录扫描最多遍历 20,000 个工作区目录。
这里只返回当前用户的文件元数据；目录可见性与后台文件导出的字节范围分别受各自限制。扫描会话、项目、文件与工作区目录均有独立上限；结果应公开返回
`truncated`、`failed_count` 与来源覆盖说明，不能把当前扫描结果伪装成完整索引。搜索只匹配文件名、对话名和
项目名，不读取或索引文件正文。Gateway reader 仍是归属和访问 URL 的权威来源；Flow Desk 产品扩展可在自己的迁移链中保存
owner-scoped 元数据快照，并按 TTL 重建、失败时保留旧快照。Gateway 删除成功后，产品 API 可以只失效该 owner 的缓存元数据行；这不执行文件删除。
该产品缓存不能反向成为 Gateway 授权来源，也不能保存正文或宿主路径。
新增来源时复核可访问 URL、删除语义、分页稳定性和跨用户隔离测试。
