# Flow Desk 本地快速启动指南

本文面向 Windows + PowerShell，说明如何第一次准备并启动 Flow Desk，以及以后如何再次启动。命令在仓库根目录 `D:\project\deer-flow` 执行，除非命令前特别写明要切换目录。

## 当前推荐的启动方式

完整服务通常由 Gateway、前端和 Nginx 组成，统一入口为 `http://localhost:2026`。如果本机没有 Docker、GNU Make 或 Nginx，也可以直接运行 Gateway 和前端：前端会将 API 请求转发到本机 Gateway，访问地址为 `http://localhost:3000`。

当前工作区已验证本机模式可用：后端依赖位于 `backend/.venv`，前端依赖位于 `frontend/node_modules`。扩展已安装并配置好后，日常启动只需要这两个依赖目录，不需要 `make` 或 Docker；首次安装 Flow Desk 扩展仍需要 `uv`。

Flow Desk 的产品 API 由仓库内的可信 Gateway 扩展提供。全新 checkout 若尚未安装此扩展，需先按下文完成一次性安装；扩展未安装时，前端基础路由仍能启动，但自有设置、管理和后台数据任务没有对应的产品 API。

## 最快启动（依赖与配置已准备好）

用两个 PowerShell 窗口分别启动后端和前端。窗口一运行 Gateway：

```powershell
Set-Location D:\project\deer-flow
$repo = (Get-Location).Path
$env:DEER_FLOW_PROJECT_ROOT = $repo
$env:DEER_FLOW_HOME = Join-Path $repo 'backend\.deer-flow'
$env:DEER_FLOW_CONFIG_PATH = Join-Path $repo 'config.yaml'
$env:DEER_FLOW_EXTENSIONS_CONFIG_PATH = Join-Path $repo 'extensions_config.json'
Set-Location (Join-Path $repo 'backend')
& '.\.venv\Scripts\python.exe' -m uvicorn --env-file '..\.env' --host 127.0.0.1 --port 8001 app.gateway.app:app
```

窗口二运行前端：

```powershell
Set-Location D:\project\deer-flow\frontend
$env:PORT = '3000'
$env:DEER_FLOW_INTERNAL_GATEWAY_BASE_URL = 'http://127.0.0.1:8001'
$env:DEER_FLOW_DEV_BUNDLER = 'webpack'
pnpm dev
```

等前端显示 `Ready` 后打开 `http://localhost:3000`。第一次启动请先完成后文的“首次启动”准备步骤；以后再次启动无需重复复制配置或安装依赖。

## 首次启动

### 1. 打开 PowerShell 并进入仓库

```powershell
Set-Location D:\project\deer-flow
```

确认关键目录和文件存在：

```powershell
Test-Path .\config.yaml
Test-Path .\extensions_config.json
Test-Path .\.env
Test-Path .\frontend\.env
Test-Path .\backend\.venv\Scripts\python.exe
Test-Path .\frontend\node_modules\next\dist\bin\next
```

配置和依赖路径的检查结果应为 `True`。如果配置或环境文件缺失，继续第 2 步；如果依赖目录缺失，按第 4 步准备依赖。

### 2. 准备配置文件

只复制缺少的文件，不覆盖已有配置：

```powershell
if (-not (Test-Path .\config.yaml)) {
  Copy-Item .\config.example.yaml .\config.yaml
}
if (-not (Test-Path .\extensions_config.json)) {
  Copy-Item .\extensions_config.example.json .\extensions_config.json
}
if (-not (Test-Path .\.env)) {
  Copy-Item .\.env.example .\.env
}
if (-not (Test-Path .\frontend\.env)) {
  Copy-Item .\frontend\.env.example .\frontend\.env
}
```

如果 `config.yaml` 已存在，不要运行 `make config`，也不要为了启动而删除它。`make config` 遇到已有主配置会主动停止，这是为了保护本地设置。

打开根目录的 `config.yaml`，确认 `models` 中至少配置并启用了一个模型。模型的 `api_key` 通常引用环境变量；在根目录 `.env` 中填入对应的真实 API Key。例如配置引用 `$DEEPSEEK_API_KEY` 时，就在 `.env` 中设置 `DEEPSEEK_API_KEY=你的密钥`。不要把真实密钥写进 `config.example.yaml` 或提交到 Git。

### 3. 确认端口空闲

本机模式需要 Gateway 的 `8001` 和前端的 `3000` 端口。检查端口：

```powershell
Test-NetConnection 127.0.0.1 -Port 8001
Test-NetConnection 127.0.0.1 -Port 3000
```

如果检查显示端口已连接，说明已有进程正在使用该端口。先关闭之前启动的服务窗口；不要直接结束来源不明的进程。

### 4. 准备项目依赖

如果以下两个依赖目录都存在，可跳过本步：

- `backend/.venv`
- `frontend/node_modules`

如果后端虚拟环境不存在，需要安装 Python 3.12 和 `uv`，然后执行：

```powershell
Set-Location D:\project\deer-flow\backend
uv sync --locked
```

如果前端依赖不存在，需要安装 Node.js 22 和仓库指定的 pnpm，再执行：

```powershell
Set-Location D:\project\deer-flow\frontend
pnpm install --frozen-lockfile
```

依赖安装只需在首次准备或锁文件变更后执行。回到仓库根目录：

```powershell
Set-Location D:\project\deer-flow
```

### 5. 一次性安装 Flow Desk 自有扩展

这一步只在当前 checkout 尚未安装 `flow-desk-product` 时执行。Python 扩展会以 Gateway 进程权限运行；先确认源码来自本仓库的 `product/backend-extension`。安装器会把源码快照放入本仓库的 `backend/extensions/sources/`，更新 `backend/pyproject.toml`、`backend/uv.lock` 和本地虚拟环境，并在根目录 `config.yaml` 注册插件；不会修改 Windows 全局配置。以后只需在扩展源码升级后重新构建/更新，不要每次启动都重新安装。

```powershell
Set-Location D:\project\deer-flow
$env:DEER_FLOW_PROJECT_ROOT = (Get-Location).Path
$env:DEER_FLOW_CONFIG_PATH = Join-Path (Get-Location).Path 'config.yaml'
$env:DEER_FLOW_EXTENSION_SOURCE = (Resolve-Path '.\product\backend-extension').Path
Set-Location '.\backend'
uv run --frozen --no-group extensions deerflow extensions install --source-env __flow_desk_source__ --yes --required
```

该一次性安装命令需要可用的 `uv`。如果当前终端找不到它，应先按仓库的开发环境准备流程提供 `uv`；无需为此修改系统级 PATH。无论本次是否需要安装，在 `config.yaml` 找到 `name: flow-desk-product` 对应的插件项，只在该项现有 `config` 中确认或合并下面的开关，保留安装器生成的 `package`、`use`、`enabled` 和 `required` 等字段：

```yaml
config:
  features:
    administration: true
  data_jobs:
    enabled: true
```

`administration` 控制管理员页面入口，服务端仍会校验管理员身份；`data_jobs.enabled` 开放本人范围的数据导出/删除任务。受支持数据 ZIP 仍标记为 `partial`，不等于完整账号备份。保存配置后再启动 Gateway。

### 6. 启动 Gateway

在第一个 PowerShell 窗口运行以下命令。这个窗口保持打开，Gateway 日志会显示在这里：

```powershell
Set-Location D:\project\deer-flow
$env:DEER_FLOW_PROJECT_ROOT = (Get-Location).Path
$env:DEER_FLOW_HOME = Join-Path (Get-Location).Path 'backend\.deer-flow'
$env:DEER_FLOW_CONFIG_PATH = Join-Path (Get-Location).Path 'config.yaml'
$env:DEER_FLOW_EXTENSIONS_CONFIG_PATH = Join-Path (Get-Location).Path 'extensions_config.json'
New-Item -ItemType Directory -Force -Path $env:DEER_FLOW_HOME, '.\backend\sandbox' | Out-Null
Set-Location '.\backend'
& '.\.venv\Scripts\python.exe' -m uvicorn --env-file '..\.env' --host 127.0.0.1 --port 8001 app.gateway.app:app
```

看到 Uvicorn 开始监听 `127.0.0.1:8001` 后，保持这个窗口运行。

### 7. 启动前端

打开第二个 PowerShell 窗口，运行：

```powershell
Set-Location D:\project\deer-flow\frontend
$env:PORT = '3000'
$env:DEER_FLOW_INTERNAL_GATEWAY_BASE_URL = 'http://127.0.0.1:8001'
$env:DEER_FLOW_DEV_BUNDLER = 'webpack'
pnpm dev
```

看到 Next.js 显示 `Ready` 后，保持窗口运行并访问：

```text
http://localhost:3000
```

首次使用时，如果页面进入初始化流程，按提示创建管理员账号；如果显示登录页，则使用已有账号登录。

### 8. 验证服务

可以在第三个 PowerShell 窗口检查 Gateway 健康状态和前端页面：

```powershell
Invoke-WebRequest http://127.0.0.1:8001/health -UseBasicParsing
Invoke-WebRequest http://127.0.0.1:3000/ -UseBasicParsing
```

两条请求都应返回 HTTP `200`。打开网页后发送一条测试消息，确认模型配置和 API Key 可用。

## 页面无法访问时先检查服务状态

浏览器显示“无法访问此网站”或 `ERR_CONNECTION_REFUSED` 时，先检查服务是否在对应端口监听；不要先修改代理、防火墙，也不要删除依赖。

在 PowerShell 中查看前端和 Gateway：

```powershell
Get-NetTCPConnection -LocalPort 3000 -State Listen -ErrorAction SilentlyContinue
Get-NetTCPConnection -LocalPort 8001 -State Listen -ErrorAction SilentlyContinue
```

- **3000 没有结果：** Next.js 尚未启动，或启动时已报错。检查前端窗口，等待它明确显示 `Ready` 后再打开页面。
- **3000 有监听，但网页仍无法响应：** 检查前端窗口输出的地址和错误；不要结束来源不明的进程。
- **网页能打开，但提示 API 或网关连接失败：** 再检查 8001，并请求 `http://127.0.0.1:8001/health`。这是 Gateway 状态，与前端 3000 是否启动是两项独立检查。

## 以后再次启动

配置和依赖准备完成后，不要重新复制配置、安装依赖或运行 `make config`。每次启动只需打开两个 PowerShell 窗口。

**窗口一：Gateway**

```powershell
Set-Location D:\project\deer-flow
$repo = (Get-Location).Path
$env:DEER_FLOW_PROJECT_ROOT = $repo
$env:DEER_FLOW_HOME = Join-Path $repo 'backend\.deer-flow'
$env:DEER_FLOW_CONFIG_PATH = Join-Path $repo 'config.yaml'
$env:DEER_FLOW_EXTENSIONS_CONFIG_PATH = Join-Path $repo 'extensions_config.json'
Set-Location (Join-Path $repo 'backend')
& '.\.venv\Scripts\python.exe' -m uvicorn --env-file '..\.env' --host 127.0.0.1 --port 8001 app.gateway.app:app
```

**窗口二：前端**

```powershell
Set-Location D:\project\deer-flow\frontend
$env:PORT = '3000'
$env:DEER_FLOW_INTERNAL_GATEWAY_BASE_URL = 'http://127.0.0.1:8001'
$env:DEER_FLOW_DEV_BUNDLER = 'webpack'
pnpm dev
```

然后打开 `http://localhost:3000`。运行期间不要关闭这两个终端窗口。

## 停止服务

分别切换到 Gateway 和前端窗口，按 `Ctrl+C` 停止对应服务。两个服务都停止后，浏览器页面将无法访问；下次使用时按“以后再次启动”重新运行即可。

## 常见问题

### `make` 不是可识别的命令

这表示 GNU Make 不在当前终端的 `PATH` 中。上面的本机模式不依赖 `make`，使用指定的 Python 虚拟环境和 `pnpm` 命令即可启动。

### `make config` 提示配置已存在

这是保护行为。保留已有的 `config.yaml` 并继续启动；如果只缺 `.env` 等环境文件，按第 2 步的 PowerShell 命令补齐。

### 找不到 `backend/.venv/Scripts/python.exe`

后端虚拟环境还未创建。安装 Python 3.12 和 `uv`，然后在 `backend` 目录执行 `uv sync --locked`。

### 找不到 `pnpm` 或前端依赖

安装 Node.js 22 与仓库要求的 pnpm；在 `frontend` 目录执行 `pnpm install --frozen-lockfile`。

### 前端能打开，但模型无法回复

先确认 Gateway 窗口没有启动错误，再检查 `config.yaml` 启用的模型和 `.env` 中对应的 API Key。修改配置后，在 Gateway 窗口按 `Ctrl+C`，重新运行 Gateway 启动命令。

### “工作台偏好”无法读取

先确认已登录并且 Gateway 的 `/health` 返回 `200`。再检查公开产品路由：

```powershell
try { (Invoke-WebRequest http://127.0.0.1:8001/api/product/v1/public-brand -UseBasicParsing).StatusCode } catch { $_.Exception.Response.StatusCode.value__ }
```

如果返回 `404`，通常是当前 checkout 尚未安装或启用 Flow Desk 产品扩展；按上文第 5 步使用仓库的扩展管理器安装，核对 `config.yaml` 的 `plugins` 项，再重启 Gateway。不要用前端本地存储代替产品 API：偏好按登录用户隔离并保存在扩展自己的数据库中。`401` 表示需要先登录，`5xx` 应查看 Gateway 日志。

### “智能体”入口不可用

自建智能体管理由根目录 `config.yaml` 的 `agents_api.enabled` 独立控制，默认值为 `false`；它与 Flow Desk 产品扩展是两个不同开关。启用前应确认 Gateway 位于可信认证边界内，并检查部署时的监听地址和访问控制。更改该配置后重启 Gateway，再以已登录账号查看 `/api/features` 的 `agents_api.enabled`。未登录时该接口返回 `401`，不代表智能体定义已丢失。

页面显示“智能体功能未启用”表示功能探测已得到明确的关闭结果；若显示“暂时无法确认智能体是否可用”，则是探测请求失败，可在页面重试并查看 Gateway 连通性。浏览器记住的上次开关值只用于避免误发管理请求，不能把本次连接失败当作新的关闭结果。

探测失败时，工作台首页仍显示通往智能体错误页的入口，方便重试；状态未确认之前不会请求自建智能体目录。若产品管理员主动关闭了智能体展示开关，首页仍会隐藏该入口。

### `localhost:2026` 无法打开

本指南的双窗口本机模式没有启动 Nginx，入口是 `http://localhost:3000`。要使用统一入口 `2026`，需另行安装并启动 Nginx，或配置可用的 Docker Compose 环境。

## 端口速查

| 地址 | 用途 |
| --- | --- |
| `http://localhost:3000` | 本指南的前端入口 |
| `http://localhost:8001/health` | Gateway 健康检查 |
| `http://localhost:2026` | Nginx 统一入口；本机双窗口模式默认不启动 |
